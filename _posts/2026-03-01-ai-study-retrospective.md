# 유튜브로 보기만하다가 AI로 랜딩페이지 만들기

부산에서 AI 스터디를 시작했다.

각자 관심사와 해결하고 싶은 문제를 가져와서, 1시간 동안 직접 만들어보는 소모임이다. 누가 발표하고 듣는 형식이 아니라, 각자의 문제를 AI로 부딪혀보는 실전 위주 모임.

나는 **밀프레드(교육용 요리키트 브랜드)의 사업계획서를 랜딩페이지로 바꿔보고 싶었다.** 단순히 "랜딩페이지 만들어줘" 한 마디로 끝내는 게 아니라, 유튜브로 접했던 **하네스(Harness)**, **오케스트레이션(Orchestration)** 개념을 작게나마 직접 시도해보고 싶었다. 잘 될지는 모르겠지만, 일단 해보자는 마음이었다.

---

## 일단 파이프라인부터 잡아봤다

전체 흐름을 이렇게 나눠봤다.

**레퍼런스 자료 분석 → 리서치 → 디자인 → 설계 → 개발 → 테스트**

각 단계가 선행 의존적이긴 하지만, 독립적으로 진행할 수 있는 부분들은 세션을 나눠서 병렬로 돌려봤다. 기획 리서치를 돌리는 동안 비주얼 리서치를 따로 태우고, 디자인 토큰이 확정되면 개발 아키텍처 설계를 동시에 진행하는 식이었다. 각 단계의 결과물은 파일로 저장해서 폴더의 데이터 정합성을 유지하려고 했다.

![기획서 v3 — 마크다운으로 작성한 기획서와 렌더링 결과](/assets/img/2026-03-01/planning-v3.png)
_설문 280건 분석 기반으로 AI가 작성한 기획서 v3. 왼쪽이 마크다운 원본, 오른쪽이 렌더링 결과다._

---

## 이렇게 나왔다

**밀프레드 소개 페이지** — 교육용 요리키트가 뭔지 소개하고, 선생님들이 무료 샘플 신청을 할 수 있는 랜딩페이지다. 설문조사 280건 분석 기반의 설득 구조, 15개 섹션, 디자인 시스템까지 포함된 결과물이 나왔는데, 솔직히 이 정도가 나올 줄은 몰랐다.

![랜딩페이지 메뉴 섹션](/assets/img/2026-03-01/landing-menu.png)
_완성된 랜딩페이지의 메뉴 섹션. 실제 밀프레드 요리키트 사진들이 들어간다._

![랜딩페이지 Problem 섹션](/assets/img/2026-03-01/landing-problem.png)
_설문 데이터에서 뽑아낸 선생님들의 고충 5가지. "몰라서 안 쓴다 64%"가 핵심 인사이트였다._

---

## 해보면서 느낀 것들

### 1. 권한을 많이 주니까 무섭긴 한데, 내가 놓친 걸 찾아온다

AI에게 로컬 폴더 접근 권한을 넘겼더니, 내가 까먹고 있던 **PL보험 인증서, 수의계약서** 같은 신뢰 자산을 알아서 발굴해서 랜딩페이지에 반영했다. 설문 데이터에서 **"몰라서 안 쓴다 64%"** 라는 인사이트도 AI가 먼저 뽑아냈다. 프롬프트에 넣지도 않은 건데. 권한을 넓게 줄수록 내 시야 밖의 것들을 가져오는 것 같다는 생각이 든다. 물론 방향이 틀어지면 1,000줄짜리 코드를 통째로 버려야 할 수도 있어서, 이게 맞는 건지는 아직 잘 모르겠다.

### 2. 한 번의 프롬프트로는 안 되더라

처음에는 한 방에 될 줄 알았다. 근데 안 됐다. 디자인 단계만 해도 Phase 1(비주얼 리서치) → Phase 2(디자인 토큰 확정) → Phase 3(전체 구현) → Phase 4(QA)로 나눠야 했다. Phase 2에서는 컬러 팔레트 옵션 A/B를 프리뷰 HTML로 뽑아서 비교했고, Phase 3 구현 후에는 스크린샷 보면서 디테일을 잡았다.

![Phase 1 비주얼 리서치 — 컬러 팔레트 A/B 비교](/assets/img/2026-03-01/visual-research.png)
_AI가 만든 컬러 팔레트 옵션 A(오렌지+네이비)와 B(오렌지+모던 브라운) 비교 화면._

각 단계에서도 sub 단계를 두고 점검하고 피드백해야 쓸 만한 퀄리티가 나오는 것 같다. "랜딩페이지 만들어줘" 한 마디로는 템플릿 수준이 한계라는 걸 체감했다.

### 3. 병렬 진행했더니 병목이 나였다

기획 세션, 디자인 세션, 개발 아키텍처 세션을 동시에 돌렸는데, 세션 간 전환할 때 맥락을 잃은 건 AI가 아니라 **나**였다. 기획 세션에서 결정한 카피 톤이 디자인 세션에 제대로 전달됐는지 내가 헷갈린 적이 있다. 병렬 처리의 병목이 AI가 아니라 내 context switching 능력이라는 걸 알게 됐는데, 이건 좀 부끄러웠다.

### 4. save = commit 이라는 걸 뒤늦게 깨달았다

밀프레드 프로젝트에서는 `SAVE_STATE.md`, `ARCHITECTURE_PLAN.md` 같은 세이브 포인트 파일을 단계마다 만들었다. 세션이 끊기거나 컨텍스트 윈도우가 넘쳐도, "이 파일 읽어" 한 마디면 전체 맥락이 복원된다.

![Claude Code에서 세이브 포인트 저장하는 장면](/assets/img/2026-03-01/save-state.png)
_"게임파일처럼 지금 상태를 저장할 수 있어?" 라고 물었더니 메모리에 저장해줬다. 돌아올 때 "밀프레드 랜딩페이지 이어서 하자" 하면 바로 이어진다._

git commit처럼 진행 상황을 스냅샷으로 남기는 게 AI 협업에서는 꽤 중요한 것 같다. 안 하면 처음부터 다시 설명해야 해서 시간이 두 배로 든다.

### 5. AI의 천장이 결국 나의 천장인 것 같다

AI에게 "설문 280건 분석해서 설득 전략 프레임워크 짜고, 그걸 기반으로 15섹션 기획서 써" 라고 지시할 수 있었던 건, 내가 먼저 그런 워크플로우를 머릿속에 그릴 수 있었기 때문인 것 같다. 비약일 수 있는데, 내 창의력이나 상상력의 범위가 곧 AI에게 시킬 수 있는 업무의 범위가 아닐까 하는 생각이 들었다. AI한테 뭘 시킬지 모르면, AI도 뭘 해야 할지 모르는 거니까.

### 6. 투자 라운드가 좀 다르게 보이기 시작했다

엔젤투자, 시드투자 1~2억 라운드... 이게 좀 다르게 느껴지기 시작했다. 밀프레드 랜딩페이지를 만들면서 체감한 건데, 예전에 디자이너 분들의 프로젝트 무드보드가 나오려면 최소 **주 단위**였는데, 이제는 **분 단위**로 나온다. 비주얼 리서치부터 디자인 토큰 확정까지 하루 안에 끝났다. 이 생산성의 비약이 결국 고정비를 극소화하는 것 같다. 월 30만 원이면 부트스트래핑이 되는 구조. 창업자 혼자 편의점 알바하면서 **BEP까지 도달 가능한 비용 구조**가 나올 수도 있겠다는 생각이 든다. 물론 아직 해봐야 아는 거지만.

---

## 돌아보며

"AI를 잘 쓴다"는 게 프롬프트를 잘 쓰는 게 아니라, AI와의 협업 프로세스를 설계하는 능력이 아닐까 하는 생각이 든 시간이었다. 세이브 포인트, Phase Gate, 역할 분리, 결정 사항 추적 — 이런 체계가 있어야 AI에게 높은 권한을 넘기면서도 결과물의 퀄리티를 어느 정도 통제할 수 있는 것 같다.

아직 모르는 게 훨씬 많지만, 다음 스터디에서는 좀 더 복잡한 문제를 가져가볼 생각이다.
